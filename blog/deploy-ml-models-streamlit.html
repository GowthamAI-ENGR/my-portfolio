How to Deploy Machine Learning Models with Streamlit

Why Deploy ML Models?

Training a machine learning model is only half the battle. The real value emerges when non-technical stakeholders, researchers, or end users can interact with your model through a clean interface - without writing a single line of Python. Deployment bridges the gap between a Jupyter notebook and a usable application.

Among the many deployment options available - Flask APIs, FastAPI services, Docker containers, cloud functions - Streamlit stands out for its speed of development and accessibility. It lets you turn a Python script into an interactive web application in minutes, making it ideal for ML prototypes, data dashboards, and portfolio projects.

What is Streamlit?

Streamlit is an open-source Python framework designed specifically for building data science and machine learning web applications. Unlike traditional web frameworks, Streamlit requires no HTML, CSS, or JavaScript knowledge. You write pure Python, and Streamlit renders an interactive UI automatically.

Key characteristics:

  • Pure Python - no frontend code required
  • Automatic re-rendering on file changes
  • Built-in widgets for sliders, dropdowns, file uploads, and more
  • Native support for pandas DataFrames, matplotlib plots, and model predictions
  • One-command deployment to Streamlit Community Cloud

Project Structure

A typical Streamlit ML project follows a simple structure: 

my-ml-project/
├── app.py              # Streamlit application
├── model.pkl           # Serialized trained model
├── requirements.txt    # Python dependencies
└── data/
    └── dataset.csv     # Training data (optional)

The app.py file is the entry point. It loads the model, defines the UI layout, handles user input, and displays predictions.

Building the Application

Step 1: Load the Trained Model

Use joblib or pickle to load your serialized model. For production, prefer joblib as it handles scikit-learn objects more efficiently: 

import joblib
model = joblib.load('model.pkl')

Step 2: Create the User Interface

Streamlit provides simple functions for building UI elements: 

import streamlit as st

st.title("ML Prediction Dashboard")
st.sidebar.header("Input Parameters")

age = st.sidebar.slider("Age", 10, 100, 25)
glucose = st.sidebar.number_input("Glucose Level", 50, 300, 100)
bp = st.sidebar.slider("Blood Pressure", 60, 180, 120)

Step 3: Make Predictions

Process the user inputs and pass them to the model: 

import numpy as np

if st.button("Predict"):
    features = np.array([[age, glucose, bp]])
    prediction = model.predict(features)
    st.success(f"Prediction: {prediction[0]}")

Step 4: Display Results

Use Streamlit's charting capabilities to visualize results. Display prediction probabilities, feature importance, or data distributions: 

import pandas as pd

st.subheader("Input Summary")
st.dataframe(pd.DataFrame({
    'Parameter': ['Age', 'Glucose', 'Blood Pressure'],
    'Value': [age, glucose, bp]
}))

Deployment to Streamlit Cloud

Streamlit Community Cloud provides free hosting for public projects. The deployment process is straightforward:

  1. Push your project to a public GitHub repository
  2. Visit share.streamlit.io
  3. Connect your GitHub account
  4. Select the repository and entry file (app.py)
  5. Click "Deploy"

Your application will be live within minutes at a URL like your-app-name.streamlit.app.

Best Practices

  • Cache expensive operations - Use @st.cache_data or @st.cache_resource to avoid reloading models on every interaction
  • Keep requirements minimal - Only include packages actually used in your application
  • Handle errors gracefully - Validate user inputs and provide clear error messages
  • Optimize model loading - Load models once at startup, not on every rerun
  • Use session state - Maintain user-specific data across interactions with st.session_state

Real-World Example

I've deployed three ML applications using this exact approach:

  • Maternal Health Risk Prediction - Healthcare risk classification using scikit-learn
  • Crop Recommendation System - Agricultural intelligence using Random Forest
  • Movie Recommendation System - Personalized recommendations using collaborative filtering

Each project follows the same pattern: train a model in Python, serialize it, build a Streamlit interface, and deploy to the cloud.

Limitations and Alternatives

Streamlit is excellent for prototypes and portfolio projects, but has limitations for production use:

  • Limited customization compared to full-stack frameworks
  • Not suitable for high-traffic production applications
  • Limited authentication and authorization options

For production applications, consider FastAPI for REST APIs, Flask for lightweight web services, or containerized solutions with Docker and cloud platforms.

Conclusion

Streamlit democratizes ML deployment. It removes the frontend barrier, letting data scientists and ML engineers focus on what they do best - building models - while still delivering interactive, shareable applications. For portfolio projects, academic prototypes, and internal tools, it remains one of the fastest paths from model to deployment.
