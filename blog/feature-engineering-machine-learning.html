Feature Engineering for Machine Learning: A Practical Guide

Why Feature Engineering Matters

Feature engineering is the process of using domain knowledge to transform raw data into features that better represent the underlying problem to machine learning models. It is often the single most impactful step in an ML pipeline — good features can outperform a more complex model with poor features.

As Andrew Ng put it: "Applied ML is basically feature engineering." While that's a simplification, the sentiment is accurate: the quality of your features directly determines the ceiling of your model's performance.

Handling Missing Values

Real-world datasets almost always have missing values. How you handle them depends on the nature of the missingness: 

import pandas as pd
import numpy as np
from sklearn.impute import SimpleImputer, KNNImputer

# Check missing values
print(df.isnull().sum())

# Strategy 1: Drop rows with missing values (use when missing data is minimal)
df_clean = df.dropna()

# Strategy 2: Simple imputation
imputer = SimpleImputer(strategy='mean')  # or 'median', 'most_frequent'
df_imputed = pd.DataFrame(
    imputer.fit_transform(df),
    columns=df.columns
)

# Strategy 3: KNN imputation (uses similar samples to estimate values)
knn_imputer = KNNImputer(n_neighbors=5)
df_knn = pd.DataFrame(
    knn_imputer.fit_transform(df),
    columns=df.columns
)

When to use each: Mean/median for numerical features with random missingness. Most frequent for categorical features. KNN for datasets where similar rows have correlated missing patterns.

Encoding Categorical Variables

Machine learning models require numerical input. Categorical variables — like city names, product categories, or color labels — must be converted to numbers.

Label Encoding

Assigns a unique integer to each category. Simple but implies an ordinal relationship that may not exist. 

from sklearn.preprocessing import LabelEncoder

le = LabelEncoder()
df['color_encoded'] = le.fit_transform(df['color'])
# red=0, green=1, blue=2

One-Hot Encoding

Creates binary columns for each category. Avoids implying order but increases dimensionality. 

# Using pandas
df_onehot = pd.get_dummies(df, columns=['color'], prefix='color')

# Using scikit-learn (better for production pipelines)
from sklearn.preprocessing import OneHotEncoder

ohe = OneHotEncoder(sparse_output=False, drop='first')  # drop='first' avoids multicollinearity
encoded = ohe.fit_transform(df[['color']])
encoded_df = pd.DataFrame(encoded, columns=ohe.get_feature_names_out(['color']))

Target Encoding

Replaces each category with the mean of the target variable for that category. Effective for high-cardinality features (many unique categories) where one-hot encoding would create too many columns. 

# Using category_encoders (pip install category-encoders)
import category_encoders as ce

target_enc = ce.TargetEncoder(cols=['city'])
df['city_encoded'] = target_enc.fit_transform(df['city'], df['target'])

Feature Scaling

Many algorithms (SVM, KNN, neural networks, linear regression) are sensitive to feature magnitudes. A feature ranging from 0-1000 would dominate one ranging from 0-1, not because it's more important, but because it's larger.

StandardScaler (Z-score normalization)

from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X_train)
# Result: mean=0, std=1

MinMaxScaler

from sklearn.preprocessing import MinMaxScaler

scaler = MinMaxScaler()
X_scaled = scaler.fit_transform(X_train)
# Result: values between 0 and 1

Rule of thumb: Use StandardScaler as default. Use MinMaxScaler when you need bounded values (e.g., neural network inputs). Tree-based models (Decision Trees, Random Forest) don't require scaling since they make splits based on feature thresholds, not magnitudes.

Feature Creation

Sometimes the raw features don't capture the full picture. Creating new features from existing ones can reveal patterns the model would otherwise miss. 

# Date features
df['year'] = df['date'].dt.year
df['month'] = df['date'].dt.month
df['day_of_week'] = df['date'].dt.dayofweek
df['is_weekend'] = df['day_of_week'].isin([5, 6]).astype(int)

# Interaction features
df['bmi'] = df['weight'] / (df['height'] ** 2)
df['price_per_sqft'] = df['price'] / df['sqft']

# Polynomial features
from sklearn.preprocessing import PolynomialFeatures
poly = PolynomialFeatures(degree=2, interaction_only=True)

But in other domains — like housing prices or customer churn — interaction and ratio features often provide significant lifts.

Feature Selection

More features isn't always better. Irrelevant or redundant features add noise, increase training time, and can cause overfitting.

Correlation Analysis

import seaborn as sns
import matplotlib.pyplot as plt

# Correlation matrix
corr_matrix = df.corr()
sns.heatmap(corr_matrix, annot=True, cmap='coolwarm')
plt.show()

# Drop highly correlated features (threshold > 0.9)
upper = corr_matrix.where(np.triu(np.ones(corr_matrix.shape), k=1).astype(bool))
to_drop = [col for col in upper.columns if any(upper[col].abs() > 0.9)]
df_reduced = df.drop(to_drop, axis=1)

Recursive Feature Elimination

from sklearn.feature_selection import RFE
from sklearn.ensemble import RandomForestClassifier

rf = RandomForestClassifier(n_estimators=100, random_state=42)
rfe = RFE(rf, n_features_to_select=10)
rfe.fit(X_train, y_train)

selected_features = X_train.columns[rfe.support_]
print(f"Selected features: {list(selected_features)}")

A Complete Feature Engineering Pipeline

Combining these techniques into a reproducible pipeline ensures consistency between training and inference: 

from sklearn.pipeline import Pipeline
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.impute import SimpleImputer

# Define feature types
numeric_features = ['age', 'income', 'score']
categorical_features = ['city', 'gender']

# Numeric pipeline
numeric_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', StandardScaler())
])

# Categorical pipeline
categorical_pipeline = Pipeline([
    ('imputer', SimpleImputer(strategy='most_frequent')),
    ('encoder', OneHotEncoder(handle_unknown='ignore'))
])

# Combine into a single transformer
preprocessor = ColumnTransformer([
    ('num', numeric_pipeline, numeric_features),
    ('cat', categorical_pipeline, categorical_features)
])

# Use in a full ML pipeline
from sklearn.ensemble import RandomForestClassifier

full_pipeline = Pipeline([
    ('preprocessor', preprocessor),
    ('classifier', RandomForestClassifier(n_estimators=100, random_state=42))
])

full_pipeline.fit(X_train, y_train)

The pipeline approach prevents data leakage — scalers and encoders are fit only on training data and applied to test data, mimicking real-world inference conditions.

Common Mistakes

  • Fitting on test data — Always split data first, then fit transformers on training data only
  • Ignoring feature distributions — Check for skewness; log transforms can help with heavily skewed features
  • Over-engineering — Start simple; add complexity only when metrics improve
  • Ignoring domain knowledge — Talk to subject matter experts; they know which features actually matter
  • Not validating changes — Always measure the impact of feature engineering on model performance using cross-validation

Conclusion

Feature engineering is part art, part science. The techniques in this guide — handling missing values, encoding categoricals, scaling, creating interaction features, and selecting the most relevant features — form the foundation of any ML pipeline. Combined with strong model selection and proper deployment practices, good feature engineering separates working ML projects from impressive ones.
